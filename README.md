# AI 每日资讯生成器

自动抓取官方 AI 资讯源，过滤、去重、排序后生成一篇结构化的《AI 每日资讯》Markdown 稿件。
成稿中为重要新闻预留**截图占位符**，由人工在审核时手动补充官方页面截图。

```
抓取(10源) → 时间过滤 → 去重(URL+标题相似度+实体重叠) → 关键词排序 → 正文提取 → LLM 成稿 → 写入 Markdown
```

## 快速开始

```bash
# 1. 创建虚拟环境并安装依赖
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2. 预览成稿格式（内置示例数据，不联网）
.venv\Scripts\python.exe main.py --demo

# 3. 正式运行（未配置 LLM 时输出列表版）
.venv\Scripts\python.exe main.py
```

产物：`output/YYYY-MM-DD/AI早报-YYYY-MM-DD.md`。同一天重复运行会依次生成 `AI早报-YYYY-MM-DD-1.md`、`-2.md`，不会覆盖历史稿件。

成稿版式参考公众号「AI 早报」类日刊：开头是按 **要闻 / 开发生态 / 产品应用 / 行业动态** 分组的**概览**（带 `#N` 编号），每条新闻一个独立小节——`## 中文标题 #N` + `>` 引用的 TL;DR 摘要 + 短段落正文（关键实体加粗、数字用反引号）+ 截图占位 + 代码块包裹的原文链接列表。标题、分类、TLDR、正文由 LLM 逐条撰写，编号、概览、占位符、链接块由代码确定性拼装，保证编号不错位。

**报道立场**：本报告以第三方视角直接报道第一方事实（"阿里发布…"而非"量子位报道称…"）。喂给 LLM 的素材不带媒体署名，Prompt 硬性禁止转述措辞（报道称/据报道/文章提到）和来源媒体名；来源统一由系统附在文末，正文不出现。

## 配置 LLM（可选，推荐）

配置后成稿为「今日头条详写 + 要闻速览 + 论文与开源」的完整资讯稿；不配置则输出结构化列表版，功能完整可日常使用。

任意 OpenAI 兼容接口均可（智谱 / DeepSeek / OpenAI…），在 `config/config.yaml` 的 `llm` 段改 `base_url` 和 `model`，然后设置环境变量：

```powershell
# PowerShell（当前会话有效）
$env:LLM_API_KEY = "你的key"

# 永久生效
setx LLM_API_KEY "你的key"
```

## 截图占位符审核流程

运行后稿首自动生成「审核清单」表格，正文对应位置有占位图。补充截图只需三步，**不需要改稿**：

1. 打开清单中某条的「原文」链接；
2. 截取页面首屏；
3. 按清单给出的路径保存（如 `output/2026-08-30/assets/2026-08-30/01-xxx.jpg`）。

保存后重新打开 Markdown，图片会自动显示在正文中。全部补完后可删除「审核清单」小节。
（占位符数量由 `config.yaml` 的 `screenshot_count` 控制，默认前 5 条。）

**定稿**：审核后从草稿挑出要发布的条目，运行（编号见草稿概览，按终稿顺序给出）：

```bash
python finalize.py 1 2 4 5 7
```

生成 `output/{日期}/AI早报-{日期}-终稿.md`：条目文字原样保留、重新编号 `#1..#N`、概览按分类重排；**正文条目不带链接块**（草稿里的链接块仅供截图时对照原文），全部信息源统一列在文末「🔗 信息源」小节；已手动插入图片的条目自动跳过占位符，审核清单只列仍缺图的条目。

**导出不覆盖历史**：同一天反复导出会自动加序号（`终稿.md`、`终稿-1.md`、`终稿-2.md`…），每一版都保留。

**单条导出**：左侧每个条目行末的「⬇」按钮，把该条目单独导出为 `AI早报-{日期}-单条-{编号}.md`（轻量结构：标题 + 正文 + 截图 + 来源，同样不覆盖历史）；命令行为 `python finalize.py --single 5`。

## Web 控制中心

```bash
python webui.py    # 或双击 webui.bat，浏览器自动打开 http://127.0.0.1:8765
```

- **桌面端**：安装依赖后双击 `desktop.bat`（或运行 `python desktop.py`），会打开一个桌面窗口；内部复用同一套 Flask WebUI，方便快速修改和排错
- **手动采集/成稿**：点「采集/成稿」会在后台运行 `main.py`，页面显示实时日志；运行期间按钮会禁用，避免重复触发，完成后自动刷新最新草稿
- **编辑草稿**：左上角选日期，右侧左栏直接编辑 Markdown（Ctrl+S 保存），右栏实时预览
- **截图入库**：编辑区上方会为每条需要截图的资讯显示独立的「资讯截图存放区」卡片。点击对应卡片后 **Ctrl+V**，截图会自动命名、保存并插入该资讯，右侧立即预览；再次粘贴可替换。编辑器内原有的 Ctrl+V 自由插图仍然保留
- **选择条目**：左侧按编号勾选要编入终稿的条目（🖼 标记表示该条目已有截图）
- **导出终稿**：点「导出终稿」先进入顺序预览；确认后同时生成 Markdown 和 PDF。PDF 会把本地截图真正嵌入文件，不依赖原图片目录，适合整体复制或发送
- **复制发布版**：点「复制发布版」会读取当前日期最新终稿，转换为富文本 HTML，并尽量把本地相对图片内嵌为 data URL 后写入剪贴板；若目标平台不接受内嵌图片，仍需要走该平台的图片上传接口或手动上传

终稿装配逻辑与 `finalize.py` 命令行共用同一份代码。

## 配置说明

`config/config.yaml`：时间窗口 `time_window_hours`、收录上限 `top_n`、截图占位数 `screenshot_count`、LLM 设置、输出路径、SQLite 路径。

`config/sources.yaml`：数据源列表。字段说明：

| 字段 | 说明 |
|---|---|
| `type` | `rss`（通用 RSS/Atom）、`hackernews`（HN 官方 API）、`changelog`（Markdown 更新日志）、`html_updates`（无 RSS 的官方公告/更新页面） |
| `weight` | 官方源权重，排序加分项（1~3） |
| `category` | `news`（默认）/ `dev`（归入"开发生态"小节）/ `product`（"产品应用"）/ `paper`（"论文与开源"） |
| `require_ai` | `true` 时做 AI 关键词准入过滤，适合 HN 这类综合源 |
| `min_score` | 仅 HN 源：最低热度分 |
| `item_limit` / `link_base` | 仅 changelog 源：最多取最近几个版本 / 条目链接指向的页面（默认为 url 本身） |
| `site` | 仅 `html_updates`：站点适配器，目前支持 `zhipu` / `qwen` / `workbuddy` / `qoder` / `moonshot` / `deepseek` |
| `code` | 仅 Qwen：官方页面配置接口的栏目代码，默认 `news.news-list` |

加新源只需在 `sources.yaml` 追加条目，不用改代码。

## 运行方式

- **手动运行**：双击项目根目录的 `run.bat`（窗口会显示进度，结束后暂停等待关闭）
- **自动运行**：已注册 Windows 计划任务「AI每日资讯」，每天 20:00 触发，输出写入 `logs/run.log`

管理计划任务：

```bat
schtasks /Query /TN "AI每日资讯" /V /FO LIST   :: 查看状态
schtasks /Change /TN "AI每日资讯" /ST 21:00    :: 改时间
schtasks /Delete /TN "AI每日资讯" /F           :: 删除任务
```

注意：

- 计划任务要在 20:00 跑出 LLM 成稿，key 必须用 `setx LLM_API_KEY "你的key"` 写入用户环境变量（计划任务读不到某个终端窗口里的临时变量）
- 20:00 时如果电脑关机，当天不会补跑；可随时双击 `run.bat` 手动补
- 同一天重复运行是安全的：没有新条目时会跳过成稿，不会覆盖已有稿件

## 常见问题

- **某源显示 [fail]**：单源失败不影响整体，通常是网络波动或对方反爬；持续失败可检查 URL 是否变更。
- **当天稿子只有几条**：官方博客发布频率低，周末尤其少。可放宽窗口 `python main.py --hours 48`。
- **LLM 调用失败**：自动退化为列表版，日志会打印原因（key 失效、余额不足、超时等）。
- **同一条新闻重复出现**：跨天去重靠 `data/news.db`，删除该文件会清空历史记录（次日会重发旧闻）。
